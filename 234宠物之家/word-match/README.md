# 默契猜词

入口为游戏大厅 `games.html`，独立页面 `word-match/`。无需登录，昵称选填；创建六位数字房间后，可复制邀请链接或房间码，好友主动加入。两人每轮各自输入一个词，双方提交后共同揭晓。答案不同则双方准备后继续，答案相同则完成测试并显示轮数；双方同意可以重新开始。

词语为1–20个Unicode字符，比较时进行NFKC规范化、去除首尾空格、连续空白合并、英文转小写。拒绝控制字符、隐藏格式字符及未配对代理字符。显示使用文字节点，不插入用户HTML。没有倒计时或人为回合上限；页面仅保留最近200轮联想记录，累计轮数持续增加。

`model.mjs`包含独立双人状态机。每轮先用32字节随机盐及SHA-256提交摘要，双方摘要齐全后才交换答案与随机盐；收到的答案必须通过摘要校验。拒绝提前揭晓、修改已锁定答案、不同对局或未来回合消息，重复包幂等处理。下一轮及重新开始均需双人同意。关闭连接会取消尚未完成的摘要操作，保留已揭晓记录供查看。

前端复用`room-config.js`和`relay.js`，只使用网站现有云房间通道，不加载PeerJS或额外运行库。服务端须登记：

```python
RULES['word-match'] = '234-word-match-v1-'
```

房间接口为`/v1/relay/word-match/{六位房间码}`。房间仅有两个位置，与其他游戏隔离。刷新、离开或断网会结束本局，可重新创建；网页不会宣称能够断线续局。不会自动给好友发送站内消息，也不新增账号或云存档模块；词语仅用于当前对局，不保存到服务器数据库。

本地协议测试：`node --test "234宠物之家/word-match/model.test.mjs"`。浏览器联机回归脚本保留在配套服务目录`test-word-match-browser.cjs`，覆盖双客户端邀请、隐藏答案、揭晓、下一轮、匹配、再玩、断线和手机布局。部署前须先在现有房间服务登记类型并通过公网配对测试，再发布GitHub Pages页面。
