# 钓鱼模拟器 1.1

2026-11-14。现有 GitHub Pages 下的独立 2D Canvas 游戏，无构建步骤和第三方素材下载。账号服务仅保存进度并转发临时双人房间消息。

## 玩法

- 青岚湖、长风江、星潮海，每图四层水深、八种鱼，共24种。湖图鉴集齐后开放江，江集齐后开放海；已解锁地图可以自由重访。鱼种重量和售价为游戏参数。
- 空钩7–11秒咬钩，有鱼饵3–6秒；偏好鱼饵的同层鱼抽取权重为3.5，其余为1。不使用鱼饵也可完成全部图鉴。鱼饵是永久配方，无消耗，可随时在收竿后换用。
- 普通上鱼一键收获，无拉扯小游戏。承重由鱼竿和鱼线中较小者决定，超重会脱钩，装备不损坏。鱼线长度决定可选水层。
- 10档鱼竿、10档鱼线、9种鱼饵（含空钩）。仓库最多500条，可逐条或全部卖出，图鉴与最大重量永久保留；售价重新根据鱼种和重量计算。
- 游客保存于本机；登录后接入现有账号云存档，可从账号中心明确导入游客进度。钓鱼货币与网站积分分离。

## 双人

复用现有 `/v1/relay/fishing/{六位房号}?seat=host|guest&rules=234-fishing-v1-` WebSocket 转发器。创建者左侧，加入者右侧；双方需要已解锁房主所在水域。切图先结束当前同钓，再建新房间；断线回到单人，已入库鱼获不丢失。文字使用textContent显示，最多120字符，界面最多50条消息，聊天不进入云存档。

双方在同一水层等待，且共同鱼获不超过两人的装备能力时，有35%机会触发抢鱼（每第三个符合条件的抛竿组合必触发，事件结束后冷却20秒）。offer/ack/commit握手绑定本次抛竿，2.5秒过期，避免普通鱼已咬钩或收竿后单方面进入抢鱼。房主须收到好友进入同一事件的状态确认才可发奖；极端延迟导致未确认时取消本次事件。抢鱼持续7秒，房主汇总点击，最多约14次/秒，同分随机决胜，只有赢家入库，鱼获ID去重。切后台时拒绝新事件，进行中的事件/确认中连接会结束。双方成绩由房主协调，沿用朋友游戏的可信客户端机制，没有竞技反作弊保证。

## 文件和存档

`model.mjs` 处理渔具、鱼种、抽取、仓库、图鉴和解锁；`scene.mjs` 绘制三套地图；`game.mjs` 管理交互、账号和同钓协议。存档模块 `fishing`、键 `pet234-fishing-v1`、schema1。沿用账号版本冲突、历史备份、导出与隔离机制；Web Locks阻止同账号重复标签同时修改。已入库、卖鱼、购买、装备与换图即时本机保存并异步同步。不自动离线钓鱼，也不持久化尚未收获的抛竿。

服务端仅添加 MODULES 的 fishing 和 relay RULES 的 fishing；没有修改其他游戏逻辑或玩家已有存档。

## 性能与验证

静态场景离屏缓存，16条小鱼和少量水纹/气泡，像素比上限1.5，绘制上限30FPS，后台停止绘制；没有物理引擎、3D资源、外部贴图或音频。桌面Chrome模拟移动视口、CPU降速四倍约27帧/秒、3.6MiB JS堆，不等同于实体手机测量。

`node --test model.test.mjs`：初始赚钱、超重脱钩、鱼线深度、十档装备、鱼饵偏好、所有鱼可获得、图鉴解锁与重访、售卖及奖励去重、仓库上限、存档恢复校验。

浏览器：实际抛竿→上鱼→卖鱼→购买并换装，真实本地测试账号云存档往返，三地图解锁重访，两个独立浏览器通过真实WebSocket同钓、聊天、抢鱼唯一赢家、断线恢复，手机横竖布局与长按无选区。服务端测试涵盖存档权限与隔离、版本冲突、导出、两钓位、第三人拒绝及房间隔离。

## 外观、音效与完整横屏界面（2026-11-14）

24种鱼改为共享矢量描述的独立插画，具有不同体型、鱼鳍、头部、鳞纹、条纹、斑点等特征。水中、人物手边、鱼获卡、图鉴和仓库使用同一鱼种外观。Canvas按种类缓存320×160透明位图，最多24张约4.69MiB（不含画布和浏览器开销），动画帧只贴图；当前水域仅16条鱼。人物改为细节更丰富的少年/少女，静态身体分别缓存，鱼竿与鱼线独立绘制。宽屏和旋转布局读取clientWidth/Height并保持人物、鱼的比例。

成功收获在水域内展示插画、名称和重量卡片，5.5秒后隐藏，获奖仍只发生在原有land逻辑中。远端鱼获ID仅用于表现，不改变奖励。仓库每页最多24条，全部出售仍出售全部库存，防止500条复杂图形同时进入DOM。

新增FishingAudio，首次手势才创建单个AudioContext，复用噪声缓冲，最多4组并发短音效；支持抛竿入水、卷线收竿、成功收获和脱钩。音效开关本机持久化，静音淡出，无自动播放、音乐或第三方声音文件。

抛竿/收竿、水层按钮及功能工具栏都在#game-shell水域内。渔具、仓库、图鉴、水域、好友、聊天、帮助和音效开关可以在全屏内使用；所有面板与实际聊天节点保持在全屏元素内部。原生Fullscreen API与横向锁定可用时优先使用；不支持时采用固定视口沉浸布局，手机竖屏通过CSS旋转提供横向界面。退出原生全屏或点击退出恢复网页布局。浏览器不提供全屏API时，网页不能强制隐藏浏览器自身工具栏。

账户存档schema和云接口保持原样。入口缓存版本3。浏览器验证包含真实收获卡/音效解锁/静音设置、全屏出售换装、七类功能面板、双人全屏聊天、原生全屏、844×390横向及390×844旋转后备模式、退出恢复。CPU四倍降速移动视口约27.5帧/秒（30帧上限）；JS堆约3MiB，不含Canvas位图内存，也不等同实体手机测试。
