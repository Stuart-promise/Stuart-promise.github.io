# 金币大亨 1.0

2026-11-13：可游玩的第一人称增量游戏原型。网页与素材部署在现有 GitHub Pages，账号云存档复用234宠物之家的版本化存档API。

## 核心循环

房间每批2400枚金币。初始拾取1枚/1.05秒，移动1.8米/秒，携带12枚，回收机每秒接收5枚、每枚兑换1元。玩家必须把背包金币运回入口回收才能消费。拾取、背包、回收后的资金相互独立，重复卸货不会重复奖励。清空后自动补充下一批，不存在挂机收入。

12项研究分为拾取效率、搬运能力、工具进化三条路线。提升拾取量/速度/距离、金币售价、背包、移速、推车与卸货速度；集币铲→磁力收集器→旋风吸币器→感应自动收集。具有前置研究、递增价格与等级上限，工具自动装备且已获得效果叠加。所有价格、能力、边界和补货配置集中在`model.mjs`，方便后续调整。

## 操作

电脑WASD/方向键移动，拖动视角或点击画面锁定鼠标，长按空格收集；E卸货，T科技树，Esc暂停/返回。手机左摇杆移动，右侧滑动转向，长按收集按钮；走近回收机后出现卸货按钮。支持横屏、全屏及竖屏旋转坐标转换。失焦或切后台暂停。

## 存档

沿用`PetAccount.open('coin-tycoon')`；存档键`pet234-coin-tycoon-v1`，云端模块`coin-tycoon`。保存金币余额、背包、科技等级、已拾取金币ID、补货批次、位置和视角。账号间隔离，本机先保存，后台同步；冲突暂停并引导账号中心选择版本。后台/离开时尝试同步，每5秒保存位置，拾取/升级/完成回收立即落本机。网络中断可继续在本机保存，再由现有同步机制上传；游客仅保存在本机，可在账号中心明确导入空云存档。浏览器支持Web Locks时，同账号同浏览器第二个游戏页面禁止同时写入。

云端只在现有`MODULES`允许列表新增一项，沿用版本冲突检测、幂等写入、历史版本、账号导出与备份。单机游戏进度由客户端计算，没有排行榜或服务器反作弊保证。

## 渲染与来源

WebGL 2 / Three.js 0.187.0，使用官方npm发行包并校验SHA-512完整性，完整MIT许可见`vendor/THREE-LICENSE.txt`。来源：[官方仓库](https://github.com/mrdoob/three.js)、[InstancedMesh文档](https://threejs.org/docs/#InstancedMesh)。依赖保存在本网站，无运行时第三方CDN请求。房间、手部、工具和金币全部由代码建模，无生成图片或外部模型。

2400枚金币共用两批实例网格；地砖也使用实例化。渲染约57次绘制、17.5万三角形；像素比最高1.5、游戏60FPS上限、菜单12FPS、后台停止绘制。没有动态阴影、后处理或物理堆叠模拟。旧浏览器没有WebGL 2时显示操作提示。

## 验证

`node --test model.test.mjs`：经济循环、背包容量、科技前置/价格/上限、存档还原、确定性补货、房间及回收机碰撞。

本地实际账号浏览器测试：移动→装满12枚→回收12元→研究指尖→刷新和API读取一致；所有工具路径、自动拾取、重复标签防写；手机横竖屏的摇杆与右侧转向、科技树操作，无JS错误。后端测试覆盖该模块匿名拒绝、账号隔离、版本冲突、幂等重试、账号导出，以及现有账号回归。

桌面Chrome模拟844×390移动视口、CPU降速4倍，2400枚金币场景约60FPS、模拟6秒正常推进、JS堆约9MiB；不等同于低端手机实测。

## 金币山与手机长按修复

新版入口缓存版本2。游戏内文字显式禁用标准/WebKit选择与长按callout；收集按钮文字不参与指针命中。收集、摇杆、画布阻止原生触摸默认行为与选择/上下文菜单，同时保留回收按钮的触摸点击事件。长按清除先前选择，松手、取消或丢失捕获立即停止。

平铺2400枚金币升级为20880枚、最高2.88米的实体金币山。39×39高度网格、1069个有金币的柱位，每层0.06米；只绘制表面最多3层金币和一个低面数填充网格。拾取从外层推进，柱高随剩余数量下降；步行相机跟随双线性插值坡面，不能从金币山内部穿行。所有金币均可最终收集，清空再补货。

旧schema1资金、背包、科技、已拾取数量和批次保留；升级为schema2，将去重金币ID压缩为位图。完整金币山采空存档仍小于4.5KB，避免每次存储/同步两万条ID。旧版页面读取新存档会提示刷新，避免忽略压缩的已采集记录。云端沿用现有存档模块，无服务端改动。

验证：model与pile两组Node测试覆盖旧档迁移、重复拾取、堆高下降、20880枚完整耗尽、紧凑保存/恢复、碰撞及经济。浏览器覆盖手机实际长按2.6秒不中断收集、无选区、阻止上下文菜单、松手停止、回收触摸点击、科技树、横竖屏、爬坡、旧存档恢复与云端回归。桌面Chrome四倍CPU降速、844×390视口约60FPS，约26万三角形/64绘制调用/10MiB JS堆，未进行实体手机测量。
