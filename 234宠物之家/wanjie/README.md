# 万界传送门 1.0

横屏 Canvas 2D 肉鸽与餐厅经营。入口 `index.html`，无构建依赖。

- 现有 PetAccount 登录；专用 `/v1/wanjie` GET/POST 保存到自有服务器 SQLite wanjie 表。
- 服务端事务计算营业额、库存消耗、24小时离线上限、购买、培养、员工培养交换、地图与角色解锁。revision 防止跨标签/设备静默覆盖。
- 战斗模拟在浏览器进行，每20秒上传收获；刷新后可领取最近检查点。此版本不提供服务端战斗重演或强反作弊。
- 三图、固定专属武器、6武器/6被动、普通/高阶三选一、约7分钟首领与无尽模式。
- 素材使用 WebP 图集；地图新增约0.83 MiB 高清地表和透明物件。Canvas DPR 上限1.5、怪物100只加精英、投射物100、经验掉落110、效果40。
- 战斗英雄、六名员工和八名顾客各自使用独立图集。五种可操作外观均有配套站姿与4帧行走动画；餐厅有做菜、走路、坐姿。

验证：`node engine.test.mjs`。账号后端位于工作区 `pet234-account-service/wanjie.py`，测试 `test_wanjie.py`、`test-wanjie-browser.cjs`。本地测试数据库不可上传。

素材：内置 imagegen 生成。characters.webp 为8人概念图；sprites.webp 为保持角色身份和四列两行顺序、移除背景的透明编辑版；worlds.webp 为四格俯视环境图（森林、废土、赛博、餐厅）。生成提示要求Q版精细角色、清晰轮廓、无文字与装饰边框。原始PNG保存在本机生成目录，网页使用压缩WebP。

## 餐厅与手机横屏更新

餐厅营业画面使用有界队列与座位预订：顾客等位、入座、下单，固定厨师做菜，服务员取餐送到对应座位，顾客用餐离店后释放座位。最多6位可见排队顾客；离开餐厅停止动画，刷新营业收入保留当前用餐进度。营业额仍由云端按已配置员工与库存统一结算，画面不重复发钱。

手机在支持时请求原生横屏，竖屏浏览器通过页面旋转提供横屏布局，并转换触控坐标。测试覆盖座位互斥、厨师固定、完整用餐循环、旋转后的摇杆和按钮。

## 难度调整（2026-11-10）

基础生命140→125，基础攻击18→16，基础回血0.25→0.15/秒。普通怪基础生命11→13，精英180→210，首领1500→1900；波次生命成长加快，怪物移速和接触伤害提高。无尽模式生命成长间隔75→60秒，攻击也随无尽时间增长。每次培养的收益、掉落、6+6槽位、同屏实体上限和首领出现时间保持原规则，怪物不读取玩家永久培养属性。

16个相同种子、固定环形走位、随机强化的对照模拟：未培养平均生存458秒→299秒；新版本基础攻击/生命/恢复各培养5级后平均472秒。模拟用于比较版本，不能代表实际玩家胜率。

## 高清地图与实体障碍（2026-11-10）

三张战斗地图改为原尺寸地表铺砖、独立透明物件和按脚底位置排序的角色。旧四格插画仍用于传送门卡片预览。树干、岩石、废土机械和赛博建筑有实体碰撞，树冠会在遮住店长时淡出。障碍物与渲染共享位置数据，移动分段检测防止冲刺穿透，怪物绕行，击退也遵守碰撞。食材与敌人只在可通行区域生成。

地表仅缓存当前地图的镜像纹理（约8 MiB像素），物件共享一张图集；使用空间桶筛选碰撞候选，不增加怪物上限。素材和完整生成提示见 [assets/ART.md](assets/ART.md)。

验证：`node --test engine.test.mjs world.test.mjs`，覆盖8分钟战斗、三图移动/冲刺/击退、绕行、出生和采集可达性。浏览器测试覆盖实际键盘撞树、三图绘制、手机竖屏旋转后的触控和100只怪物压力场景；桌面Chrome的4倍CPU降速测试通过，但不能替代低端真机测量。原有结算、刷新和云存档回归测试通过。

## 怪物、武器、采集与步行动画（2026-11-10）

三图共用一张18种怪物图集，森林野兽/菌怪、废土变异生物/农机、赛博机械各有专属外观。精英和首领使用独立造型、不同体型、脚下标识与带名称血条。新增6种采集点外观与拾取反馈。六种投射物各有独立轮廓和拖尾；冰霜、旋风、闪电、回旋刃、荆棘和护盾各自绘制，火旋风也有专属配色。战斗数值不因美术变化调整。

男女店长、精灵游侠、废土猎手与赛博技师共20帧行走素材，根据实际移动距离切帧；停止或被障碍挡住时切回站姿。朝左镜像、朝右原图，纵向沿用最后左右朝向。新增素材约534 KiB下载、4.86 MiB解码像素，详见 [素材与完整提示词](assets/COMBAT-ART.md)。

绘制上限60 FPS，屏幕外物件跳过绘制，取消每帧为每个角色创建绘制闭包。保留100只普通怪、100枚投射物及40个特效预算；命中/采集特效最多使用24个名额，优先保留范围攻击。闪电视觉分支最多8条，真实范围伤害不受影响。普通怪预警淡化，精英和首领保留明显预警。

验证：`node --test engine.test.mjs world.test.mjs combat.test.mjs`。浏览器检查三图怪物阵容、6种投射物差异、6种范围效果、五种外观的行走/停步、竖屏旋转后的触控以及原有云存档和结算。桌面Chrome模拟844×390屏幕、CPU降速4倍，100怪加6把满级武器测得约60绘制FPS，模拟时间正常；该结果不等于低端手机实测帧率。

## 怪潮与料理探索更新（2026-11-10）

本次版本：`game.js?v=7`、`engine.mjs?v=6`、云端规则/存档版本2。

- 每60秒进入下一波。每批1→2→3→…→8只，刷新间隔1.05秒逐步缩短到0.22秒；无尽额外增加批量（仍最多8只），间隔最低0.16秒。普通怪生成队列到100个敌人时停止补充，精英与首领保留额外位置，全部敌人硬上限104；投射物100、特效40。
- 普通怪基础生命按波次16→28，再乘时间/地图成长；第5分钟森林普通怪约69生命（此前约32）。精英基础210→480，森林首领1900→4800。接触与范围攻击伤害、移动及技能频率提高。首领仍在第7分钟出现，怪物完全不读取永久培养。
- 首次升级经验5→8，后续需求为`ceil(8 + 等级*3 + 等级^1.1)`；原公式`5 + 等级*2.2`。武器每级伤害系数22%→14%、攻速13%→9%；强攻、急速、范围、领悟被动减半，活力20→12。永久培养每级收益保持原规则。
- 12种蔬果按世界分布，28个有界采集点，50秒再生；靠近自动采集，店长食材专家仍生效。采集物、库存及菜谱共用约85 KiB图集，详见[素材与生成提示](assets/FOOD-ART.md)。
- 料理研究允许任意2～3份具体食材试作，每次6金币。24道菜通过探索发现；未知菜仅提供风味线索，不向客户端发送完整配方。成功后可上架，失败记录笔记，已知配方不重复扣费。
- 最多3道营业菜，按可调整的优先级消耗真实库存。售完或无菜单时售卖每份1金币的虚空清汤。基础营业周期35→120秒，员工每级效率加成12%→7%，餐厅每级效率加成14%→6%。离线结算仍最多24小时，分次刷新与一次结算一致。
- 扩建金币100×等级²→400×等级²，并需肉15×等级、蔬菜10×等级、水果6×等级，以及`min(12,等级+1)`道已发现菜。蔬果优先扣库存最多的种类。永久培养金币60→120×下一等级²，员工培养50→140×当前等级²。
- 云端迁移保留已拥有的金币、等级、培养与角色，旧泛蔬菜等量拆分为卷心菜/胡萝卜/番茄。旧版本已开始的战斗仍可结算/恢复；新开战必须规则版本2。旧页面需要刷新。前端与素材只发布GitHub Pages，云服务器只更新账号/存档/经营API。

验证：5组Node回归（战斗8分钟、地图碰撞、怪物/武器表现、餐厅队列、蔬果及波次）；8项经营/存档测试（旧档迁移、试作原子扣费、私有未知配方、菜单库存、离线分段一致、24小时上限、扩建、账号隔离与重复领取）；账号服务基础回归。浏览器实测研发成功/失败、3菜单优先级、离线扣库存、手机横竖屏操作、采集水果结算、扩建及重载。桌面Chrome在4倍CPU降速、844×390视口、百怪六武器下约56绘制FPS，非实体手机测试。

同种子8次固定环形走位、优先武器的模拟：未培养平均约381→114秒；攻击/生命培养5级约468→174秒，15级约480→279秒。用来确认本次明显提高难度，不代表真实玩家胜率或理想走位。
